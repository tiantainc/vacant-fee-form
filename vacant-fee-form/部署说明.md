# 空置房费用在线填报工具 · 部署与分享说明

## 一、当前环境为什么不能直接给"公网链接"

本工具现在运行在一台处于**企业 VPN / 云桌面**内的机器上（本机 IP 为 `10.8.x.x` 与 `10.11.x.x` 这类私有地址）。

- 手机用流量（4G/5G）或外网**无法访问**这个 `10.x` 内网地址；
- 本环境出网受限：GitHub、SSH 隧道、cloudflared 均不可达，本地隧道（localtunnel）时灵时不灵、且链接是临时性的。

因此，**从这个环境里无法稳定地给出一个"公网可访问、可发微信群"的链接**。
要拿到真正的分享链接，需要把工具部署到你自己的、具备公网地址的账户或机器上。下面是可走的几条路，按"从快到稳"排列。

---

## 二、方案 A：在自己电脑上跑（最快验证手机效果）

适合先在自己手机上确认"填报 / 提交 / 管理员汇总"是否好用。

1. 把整个 `空置房费用填报工具` 文件夹下载（或拷贝）到你的笔记本电脑。
2. 安装 Node.js 18 及以上版本，进入该文件夹，命令行运行：
   ```bash
   node server.js
   ```
3. 电脑浏览器打开 `http://localhost:3000` 即可填报；管理员页 `http://localhost:3000/admin.html?key=admin123`。
4. **手机与电脑连同一个 WiFi** 时，手机浏览器打开 `http://<电脑内网IP>:3000`（内网 IP 用 `ipconfig` 查，通常是 `192.168.x.x`）。
   - ⚠️ 公司网络 / 手机热点通常会隔离设备，连不通就走下面的方案 B / C / D。

---

## 三、方案 B：部署到免费 PaaS（永久公网链接，推荐用于正式收集）

已为你备好零依赖 Node 服务的部署配置：`Procfile`、`railway.json`、`render.yaml`。
服务会自动读取 `PORT` 环境变量（PaaS 注入），无需改代码。

### 以 Render 为例（Railway 步骤基本一致）
1. 准备一个 GitHub 仓库，把本文件夹推上去（需能访问 GitHub 的网络环境）。
2. 打开 https://render.com → **New → Web Service** → 关联该 GitHub 仓库。
3. 关键设置：
   - Runtime：Node
   - Build Command：留空（零依赖，无需安装）
   - Start Command：`node server.js`
   - 环境变量：`ADMIN_KEY` = 你自定的管理员密码；`NODE_VERSION` = `18`
4. 部署完成后，Render 会给你一个 `https://xxx.onrender.com` 的 HTTPS 地址，可直接发微信群。
- **Railway**（https://railway.app）流程类似，已配 `railway.json`，连仓库后基本自动部署。
- 免费实例会"休眠"：一段时间无人访问后，首次打开较慢（几秒到十几秒）。
- 数据持久化：免费磁盘重启可能清空。建议在 Render 挂一个 **Disk**（对应设 `DATA_DIR=/data`）、Railway 挂 **Volume**，保证填报数据不丢。

---

## 四、方案 C：WorkBuddy 「发布为应用」

如果你在 WorkBuddy 客户端里能看到「发布为应用」入口（本次会话所在环境未挂载该能力），
用它可一键生成 HTTPS 链接 + 分享二维码，最适合直接发微信群。请在**你自己的账号 / 客户端**里操作。

---

## 五、方案 D：自有云服务器 / VPS（最稳，完全自控）

把文件夹上传到任意一台有公网 IP 的 Linux 服务器，运行：

```bash
node server.js
```

在防火墙放行端口（如直接用 3000，或用 Nginx 反代到 80/443），即可获得长期稳定的公网地址。
建议用 `pm2` 或 `systemd` 守护进程，保证后台常驻。

---

## 六、管理员与数据安全须知

- **管理员密码**：环境变量 `ADMIN_KEY`（默认 `admin123`）。正式使用前务必改成强密码，否则任何人都能进管理页。
- **填报数据**：默认写入 `data/submissions.json`（已被 `.gitignore` 忽略，不会进仓库，避免敏感数据外泄）。
- **多人重复提交同一项目**：系统自动取"最新一次"提交的值，不会重复累加。
- **持久化提醒**：在线收集多人数据时，务必确认部署环境磁盘是持久化的（见方案 B/D），否则实例重建会丢失历史填报。

---

## 七、改完代码后重新部署

改完 `public/` 下前端或 `server.js` 后，把改动推回仓库即可，PaaS 会自动重新构建部署；
自有服务器上重启 `node server.js` 进程即可生效。
